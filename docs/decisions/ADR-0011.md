# ADR-0011 — Autoridad online y límite del primer lobby

Fecha: 2026-10-18. CODEX-006. Estado: aceptada para preparación local; integración Supabase pendiente.

El modo local y sus motores permanecen independientes. `src/features/online` contiene contratos, cliente oficial y presentación online. La identidad procede exclusivamente de Supabase Auth (`signInAnonymously`); el nombre visible no concede permisos. Borrar los datos del navegador puede perder definitivamente la sesión anónima y el acceso a la sala. Dos pestañas del mismo perfil comparten identidad; no sirven como dos participantes.

PostgreSQL posee membresía, configuración, versión, fase y comandos de lobby. Las escrituras de cliente están revocadas incluso al anfitrión. RLS permite leer solo salas propias y datos privados propios. `private.room_secrets` conserva invitación y semilla; el snapshot autorizado entrega la invitación pero nunca la semilla. El ledger de comandos es exclusivo del servidor para no filtrar futuras estrategias. No hay política de escritura del navegador en ninguna tabla competitiva.

Cada RPC usa `auth.uid()`, `search_path = ''`, permisos EXECUTE explícitos, bloqueo de fila de sala y versión esperada. La clave (actor autenticado, actionId) identifica un comando; reutilizarla con otro contenido se rechaza. Repetir un comando válido no repite el efecto y recupera el snapshot actual si el actor aún pertenece. La creación necesita además un bloqueo transaccional del identificador de acción antes de crear la sala. Las consultas de snapshots bloquean la sala para no mezclar versiones de tablas distintas.

La configuración inicial acepta exclusivamente Global, 100M, once titulares, cero suplentes y tres descartes. La versión `global-150-3de32b4` identifica el catálogo Global existente sin reauditarlo; `online-lobby-v1` solo permite operaciones de lobby. Las columnas tipadas reservan ampliaciones, pero sus restricciones deben cambiar junto con los validadores del servidor. La expiración por defecto es de 24 horas, definida en el servidor. No se ofrece al cliente cambiarla.

Realtime privado transportará únicamente invalidaciones (roomId y versión); cada cliente recupera el snapshot SQL oficial. Se autoriza la recepción por pertenencia y no el envío del navegador. Al suscribirse/reconectar se vuelve a consultar para cerrar la ventana entre snapshot y suscripción. Se mantiene recuperación periódica y al recuperar foco/red porque un evento efímero puede perderse. La conexión del canal describe conectividad propia; no demuestra que el rival esté conectado. No se usa Presence como autoridad.

La fase competitiva futura reutilizará `auctionEngine.ts`, `matchConfig.ts` y simulación pura en un runtime servidor. No se copian fórmulas económicas a SQL ni React. La semilla, catálogo fijado, estrategias y resolución deben permanecer en ese runtime; la transacción SQL deberá validar versión y guardar resultado/ledger atómicamente. B permite al anfitrión pasar READY → IN_PROGRESS/COIN_TOSS con ambos listos, pero solo como transición del lobby: muestra explícitamente que moneda, subastas y partido están pendientes; no sortea ni ejecuta una operación competitiva. CODEX-006C no se inicia. Seat 1 corresponde al futuro recruiter_one y seat 2 a recruiter_two, sin confiar en esos códigos como identidad.

Temporizadores futuros: `game_state.deadline_at` y snapshot `deadlineAt`, escritos por servidor. Referencias 15/25/75/30 segundos, no activas. Un trabajador servidor deberá convertir vencimientos en comandos auditables/idempotentes; React solo representará el tiempo. Se conserva ADR-0010.

Referencias oficiales consultadas: [Auth anónima](https://supabase.com/docs/guides/auth/auth-anonymous), [Broadcast desde base de datos](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes), [autorización Realtime](https://supabase.com/docs/guides/realtime/authorization). Debe deshabilitarse Allow public access en Realtime. La persistencia oficial de la sesión contiene tokens de Auth administrados por el SDK; nunca se configura una clave privada/service role en el frontend.
